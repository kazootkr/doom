これはDoom Emacs用の個人設定ファイルです。

* 実行環境

- macOS 26(Apple Silicon)
- GNU Emacs 30.2（ビルドスクリプト: https://github.com/kazootkr/emacs-build)
  - NS port + ns-inline-patch 適用ビルド（macOS/NS 固有設定・IME 連携の前提）
  - 主要ビルドフィーチャー: TREE_SITTER / NATIVE_COMP / SQLITE3 / MODULES / GNUTLS / LIBXML2
- Doom Emacs: https://github.com/doomemacs/core
  - docker 検証環境（docker/）はホストの doom と同じコミットでイメージを作る。ホストで doom を
    更新したら =./docker/run.sh clean && ./docker/run.sh build= で作り直す
- 言語のランタイム・言語サーバーは mise で管理する。Finder/Dock から起動した GUI Emacs は
  シェルの =$PATH= を継承しないため、ホストで =doom env= を実行して取り込む（=$PATH= の構成を
  変えたら再実行する。判断の経緯は [[file:docs/decisions/lsp-client-and-runtime.org][lsp-client-and-runtime]]）


* 設定(コード)変更プロセス

変更のリスクに応じて手順を変えます（判定の目安は [[file:AGENTS.md][AGENTS.md]]）。

- 小（設定値 1 つなど）: 直接実装 → docker 検証 → コミット
- 中・高: change brief を使い、下記のスキルで進めます。
  1. =/create-brief= — プロンプト → brief（docs/changes/）
  2. =/implement-brief= — brief → 実装・docker 検証（docker/checks.el）
  3. macOS 実機で受け入れ基準を確認
  4. =/ship-brief= — 残すべき事実をコード・チェック・恒久文書へ移し、brief を削除

brief は次の変更の差分だけを書く使い捨ての文書です。挙動の正はコードと
=docker/checks.el=、経緯は git 履歴に置きます。恒久的に残す文書は次の 2 つだけです。

- [[file:docs/macos-checklist.org][docs/macos-checklist.org]] — docker で検証できない macOS 固有の確認項目
- docs/decisions/ — 調べ直すと高くつく判断の記録（ADR）

** コミット運用

各ステップの完了ごとにコミットします（小は実装で 1 回、中・高は brief 作成・実装・出荷で各 1 回）。

コミットは =/git-commit= スキルで行います。差分ファイルすべてを対象に、
Conventional Commits 形式の subject 1行（本文・フッターなし）でコミットします。
