* 背景

利用環境は macOS 26（Apple Silicon）/ GNU Emacs 30.2（NS port, =ns-inline-patch= 適用済み）。
=ns-inline-patch= は NS port の IME（インラインプレディット）連携を改善するビルドパッチで、=elisp=
パッケージではない（=packages.el= への追加は不要）。パッチ適用ビルドが次の =mac-*= 関数・変数・フックを
提供する:

- =mac-input-method-mode= — IME 連携モードの有効化。
- =mac-ime-activate= / =mac-ime-deactivate= / =mac-ime-toggle= — IME の オン/オフ/トグル。
- =mac-get-current-input-source= / =mac-ime-input-source-list= — 現在/利用可能な入力ソースの取得。
- =mac-default-input-source= — 既定の入力ソース（input source ID）。
- =mac-ime-before-put-text-hook= / =mac-ime-after-put-text-hook= — インライン入力前後のフック。

現状 =config.el= には IME 連携の設定が無い（CLAUDE.md にも「IME 連携は今後追加予定の未実装」と明記）。
そのため =M-x= 直後に IME が日本語のままで「=M-x あ=」になる、evil ノーマルステートで =hjkl= 等の
コマンドが日本語入力に化ける、といった問題が起きうる。普段は macOS 標準の日本語 IME を使うため、
編集・コマンド入力の基底状態は英数（IME オフ）にしておき、必要な場面でだけ日本語入力できるよう
制御したい。一方、ファイル内容の検索・org タグ・ToDo には日本語を使うため、それらに伴う入力では
日本語を打てる必要がある。

=doom-first= 確認: =:os macos= モジュール・=:input= 配下（=japanese= 等）に、この =ns-inline-patch=
の =mac-ime-*= による IME 制御に相当する機能は無く、=config.el= での独自設定が必要。

あわせて、NS port 環境で =diff-hl= がフリーズする既知の不具合に対処する。=:ui vc-gutter +pretty=
（[[file:../../init.el][init.el]]）が使う =diff-hl= は、doom の =vc-gutter= が =diff-hl-update-async= を
=(or (> emacs-major-version 30) 'thread)= に設定する。本環境は Emacs 30.2 のため値は =thread=
（Lisp スレッドによる非同期更新）になり、macOS NS port + Emacs 30 系 + スレッド非同期更新の
組み合わせで diff マーカー描画時に Emacs がフリーズする（[[https://github.com/dgutov/diff-hl/issues/230][dgutov/diff-hl#230]]）。これは
=ns-inline-patch= 自体に起因する不具合ではないが、同じ NS port 環境の既知問題として本要求にまとめる。

参照: =ns-inline-patch= — https://github.com/takaxp/ns-inline-patch /
diff-hl freeze — https://github.com/dgutov/diff-hl/issues/230

* 要求一覧

** req-4.1: ns-inline-patch の IME 連携を有効化し、基底を英数・既定 IME を macOS 標準にすること（必須）

=ns-inline-patch= 適用ビルドの IME 連携を有効化し、Emacs から NS port の IME を制御できる状態にすること。

- =mac-input-method-mode= を有効化し、IME 連携が効くこと。
- 編集・コマンド入力の基底状態は英数（IME オフ）とする。日本語入力で活性化する IME は macOS 標準の
  日本語 IME とする（README の例にある Google 日本語入力ではなく、macOS 標準の日本語入力ソースを
  既定の入力ソースに設定する）。実際の入力ソース ID は実機の =mac-ime-input-source-list= で確定する。
- =ns-inline-patch= 未適用ビルドや NS port 以外（Linux・docker 等）では =mac-*= 関数が存在しないため、
  当該設定はロードされず no-op になること。

** req-4.2: evil ノーマルステートで IME を自動オフにすること（必須）

evil のノーマルステートに入ったとき、IME を自動的にオフ（英数入力）にすること。これにより
=hjkl= 等のコマンドキーが日本語入力に化けて誤爆するのを防ぐ。

- ノーマルステートへ遷移したタイミングで IME がオフになること。

** req-4.3: minibuffer 入力では既定で IME をオフにすること（必須）

minibuffer での読み取りが始まるとき、既定で IME をオフ（英数入力）にすること。=M-x= や
コマンド引数の入力が英数で始まり、「=M-x あ=」のような誤入力を防ぐ。

- minibuffer 読み取り開始時に IME がオフになること（req-4.4 の例外コマンドを除く）。

** req-4.4: 特定コマンドに伴う入力では日本語入力を許可すること（IME を自動オフにしない）（必須）

ファイル内容・org タグ・ToDo には日本語を使うため、次のコマンドに伴う minibuffer 等の入力では
req-4.3 の既定オフを適用せず、日本語を入力できる（IME を自動オフにしない）こと:

- =isearch= / =isearch-forward= / =isearch-backward=
- =+default/search-project=
- =org-tags-view=
- =org-capture=
- =org-ctrl-c-ctrl-c=

これらの入力では IME のオン/日本語入力が可能であること。それ以外のコマンドでは req-4.3 の既定オフが
効くこと。

** req-4.5: NS port で diff-hl がフリーズしないこと（必須）

macOS NS port + Emacs 30.2 + =diff-hl-update-async= = =thread= の組み合わせで diff マーカー描画時に
Emacs がフリーズする不具合（dgutov/diff-hl#230）を回避し、=diff-hl=（=:ui vc-gutter +pretty=）使用中に
Emacs がフリーズしないこと。

- doom の =vc-gutter= が設定する =diff-hl-update-async=（Emacs 30 系では =thread=）を上書きし、
  スレッドによる非同期更新を無効化してフリーズを回避すること。
- vc-gutter（diff の fringe 表示）自体の機能は維持すること（無効化はあくまで非同期更新方式のみ）。

* タスクへの引き継ぎ

=ns-inline-patch= の基本セットアップ（req-4.1）の README 参照例。入力ソースは req-4.1 のとおり
macOS 標準の日本語 IME に置き換える（下記の Google 日本語入力 ID は置換対象）:

#+begin_src emacs-lisp
(when (and (memq window-system '(ns nil))
           (fboundp 'mac-get-current-input-source))
  (when (version< "27.0" emacs-version)
    (custom-set-variables
     '(mac-default-input-source "com.google.inputmethod.Japanese.base")))
  (mac-input-method-mode 1))
#+end_src

- req-4.2〜4.4 の配線（evil ステート遷移フック・minibuffer 読み取りのフック/advice・例外コマンドの
  判定方法）は、上記 =mac-ime-activate= / =mac-ime-deactivate= 等の primitive を使ってタスクで設計する。
  例外コマンド（req-4.4）の扱いは一様ではない（=isearch= は専用モード、=org-capture= は専用バッファ、
  他は minibuffer 読み取り）ため、各コマンドに合った機構へ落とし込む。
- req-4.5 は、CLAUDE.md の方針どおり =diff-hl-update-async= の上書きを素の =setq= ではなく =after!=
  （=vc-gutter= もしくは =diff-hl=）ブロックで行い、doom がロード時に設定する値を確実に上書きする。

* 非機能要求・制約

- 設定の配置先は =config.el=。IME 連携（req-4.1〜4.4）は =(when (and (eq system-type 'darwin) (featurep 'ns)) ...)=
  の darwin/NS ガード内、かつ =mac-input-method-mode= 等の =fboundp= ガードで、=ns-inline-patch= 未適用
  ビルド・対象外環境では no-op になること（既存の macOS 固有設定と同じ作法）。
- req-4.5 の =diff-hl-update-async= 上書きは =after!= ブロックで行う（doom の =vc-gutter= がロード時に
  設定するため、素の =setq= では確実に効かない）。
- =packages.el= の変更は不要。=ns-inline-patch= は Emacs ビルドへのパッチであり、=mac-*= 関数は
  パッチ適用ビルドが提供する。
- 検証環境の制約: =docker/= の検証コンテナは Linux のため、=mac-*= 関数・=ns-inline-patch=・NS port の
  IME 挙動・diff-hl のフリーズ再現/回避は検証できない。docker で確認できるのは「設定がエラーなく
  ロードできること」「対象外環境で IME 連携が no-op になること」「=diff-hl-update-async= が =nil= に
  上書きされていること」程度。IME の自動オフ・minibuffer 制御・evil 連携・例外コマンドの日本語入力・
  diff-hl がフリーズしないことの最終確認は macOS 実機でユーザーに依頼する。

受け入れ確認手順:

- [ ] =mac-input-method-mode= が有効化され、=ns-inline-patch= の IME 連携が効く（macOS 実機）
- [ ] 普段の入力基底が英数（IME オフ）で、日本語入力時に macOS 標準の日本語 IME が使われる（macOS 実機）
- [ ] evil ノーマルステートに入ると IME が自動でオフになる（macOS 実機）
- [ ] =M-x= 等の minibuffer 入力が既定で IME オフ（英数）で始まる（「=M-x あ=」が起きない）（macOS 実機）
- [ ] =isearch= / =isearch-forward= / =isearch-backward= / =+default/search-project= / =org-tags-view= /
      =org-capture= / =org-ctrl-c-ctrl-c= の入力で日本語を入力できる（IME が自動オフにならない）（macOS 実機）
- [ ] =diff-hl-update-async= が =nil= に上書きされ、=diff-hl=（=:ui vc-gutter +pretty=）使用中に Emacs が
      フリーズしない（macOS 実機）。fringe の diff 表示自体は維持される
- [ ] 設定ロード時にエラーが出ない（docker の =./docker/run.sh batch=）
- [ ] 対象外環境（Linux / docker、=ns-inline-patch= 未適用ビルド）で IME 連携が no-op となり、エラーに
      ならない（docker の =./docker/run.sh batch=）
