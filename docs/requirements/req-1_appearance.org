* 背景

Doom Emacs の見た目（フォント・テーマ・日本語表示）を整える要求。

現状 =config.el= では外観まわりが Doom の既定のままになっている:

- =doom-font= は未設定（コメントのコメント例があるだけ）。よってフォント種別・サイズ・行間は Doom 既定。
- =doom-theme= は =doom-one=。
- 日本語フォントの割り当て（フォントセット）・行間（=line-spacing=）・macOS の anti-aliasing 設定は無い。

利用環境は macOS 26（Apple Silicon）/ GNU Emacs 30.2（NS port, ns-inline-patch 適用済み）。
日本語フォントを明示しないと、Unicode の CJK 統合により日本語が中国語字形のフォントで描画されたり、
グリフ不足で豆腐（□）になることがある。macOS では Hiragino 系の日本語フォントが利用できる。

参照: JetBrains Mono — https://www.jetbrains.com/ja-jp/lp/mono/

appearance 関連で未有効の Doom モジュールも複数ある（=:ui= の =unicode= / =indent-guides= /
=nav-flash= / =emoji= / =smooth-scroll= 等）。このうち =unicode= は =unicode-fonts= に依存し、
利用可能なフォントを走査して =fontset-default= に多数のフォールバックを設定する（非ラテングリフは
=doom-symbol-font= を優先）。初回はキャッシュ生成に時間がかかり、macOS では既知の =void-variable=
エラー（回避策は unicode-fonts キャッシュの削除）や daemon 起動時のフォント設定失敗が報告されている。
そのため req-1.3 の日本語フォント設定（Hiragino 等）と干渉しないか検証が要る。=smooth-scroll= は
=ultra-scroll=（=pixel-scroll-precision-mode= 前提）でピクセル平滑化し、req-1.5 の目的と重なる。

* 要求一覧

** req-1.1: コーディング用等幅フォントを JetBrains Mono に統一すること（必須）

エディタの主フォントを JetBrains Mono にし、サイズと行間を読みやすく整えること。

- 主フォント（=doom-font=）= JetBrains Mono、サイズ 15。
- 行の高さを既定の約 1.2 倍にする（=line-spacing= による行間調整）。
- JetBrains Mono のコーディングリガチャ（=->=, =>== 等の合字）を有効化する。これには =:ui ligatures= モジュールの有効化（init.el のコメント解除）と =doom sync= が必要。=doom-symbol-font= 等との整合も合わせて確認する。
- 前提: JetBrains Mono が OS にインストール済みであること。未インストールの場合はインストールを促すこと

** req-1.2: macOS で文字を anti-aliasing 表示すること（必須）

macOS（NS port）で文字描画が滑らかな anti-aliasing になるようにすること。

- macOS / NS port 以外の環境（Linux 等）では影響を与えない（no-op）こと。

** req-1.3: 日本語が文字化け・中華フォント化せず日本語フォントで表示されること（必須）

日本語（ひらがな・カタカナ・漢字）が、専用の日本語フォントで正しく表示されること。

- 豆腐（□）や、CJK 統合による中国語字形のフォントで描画されないこと。
- 半角英数（JetBrains Mono）と全角日本語が混在しても、表示が大きく崩れないこと。
- 全角日本語の表示幅が半角英数の整数倍（2 倍）になるよう調整し、org テーブルやコメント整形の桁ズレを防ぐこと。
- macOS で利用できる日本語フォント（Hiragino 系等）を用いる。

あわせて、文章向けの可変ピッチフォント（=doom-variable-pitch-font=）に読みやすい比例フォントを設定し、org / markdown など地の文の可読性を上げること。

- 可変ピッチでも日本語が崩れない（中華フォント化・豆腐化しない）こと。
- 等幅が必要なコード・表は等幅のまま保たれること。

** req-1.4: テーマを doom-solarized-dark-high-contrast にすること（必須）

- =doom-theme= を =doom-solarized-dark-high-contrast= に変更すること。

** req-1.5: ピクセル単位のスムーススクロール

macOS のトラックパッド／マウスで滑らかにスクロールできること。あわせて PgUp/PgDn・=C-d= / =C-u=
など大きな移動も補間スクロールで滑らかに移動できること。

- Doom の =:ui smooth-scroll +interpolate= モジュール（=ultra-scroll= でピクセル平滑、=good-scroll=
  で補間）で実現する。init.el でのモジュール有効化と =doom sync= が必要。
- 必須要求（req-1.1〜1.4）より優先度は低い。

** req-1.6: appearance 関連の Doom モジュールを有効化すること

外観・可読性に寄与する =:ui= モジュールを init.el で有効化すること（=doom sync= が必要）。

- =unicode= — =unicode-fonts= による Unicode グリフのカバレッジ拡張（要望・必須）。
- =indent-guides= — インデント列をハイライトし、ネストの深いコードの可読性を上げる。
- =nav-flash= — 大きな移動の後にカーソル行を一瞬光らせ、現在位置を見失わないようにする。
- =(emoji +unicode)= — 絵文字グリフを描画する。
- =unicode= 有効化によって req-1.3 の日本語表示が退行しない（中華フォント化・豆腐化しない）こと。
  必要なら =doom-symbol-font= や日本語フォントセットの優先順位を調整する。

* 非機能要求・制約

- 設定の配置先は =config.el=。=doom-font= / =doom-variable-pitch-font= / =doom-theme= は doom 変数のため素の =setq= でよい。日本語フォントの割り当て（フォントセット）や =line-spacing=・macOS の anti-aliasing は、適切なタイミング（フォント適用後のフック等）で反映する。実装手段の詳細はタスクで設計する。
- macOS 固有の設定（anti-aliasing、Hiragino 等の日本語フォント指定）は darwin / NS port を判定するガード内に置き、Linux・対象外環境では no-op になること。既存の CLAUDE.md の方針（macOS 固有要素は darwin ガード内に置く）に従う。
- 検証環境の制約: =docker/= の検証コンテナは Linux で、JetBrains Mono・Hiragino・macOS の anti-aliasing は検証できない。docker で確認できるのは「設定がエラーなくロードでき、theme が適用されること」程度。フォント／日本語表示／中華フォント不在の最終確認は macOS 上でユーザーに依頼する。
- Doom モジュールの有効化（req-1.1 の =ligatures=、req-1.5 の =smooth-scroll +interpolate=、req-1.6 の =unicode= / =indent-guides= / =nav-flash= / =emoji=）は init.el の編集 + =doom sync= が必要。複数モジュールは 1 回の =doom sync= でまとめて反映する。docker batch は init.el 変更時に自動で =doom sync= を走らせる。
- =unicode= は初回に =unicode-fonts= キャッシュ生成で時間がかかる。macOS の既知 =void-variable= エラーが出た場合は unicode-fonts キャッシュを削除して再起動する。

- [ ] JetBrains Mono の合字（リガチャ）が表示される（=doom sync= 後にエラーなくロードできる）
- [ ] macOS で文字が anti-aliasing 表示される

- [ ] 全角日本語と半角英数の表示幅がそろい、org テーブルの桁ズレが出ない
