* 背景

Ruby/Rails・TypeScript/React・Swift・Web マークアップを LSP（lsp-mode）前提で
開発できるようにする。実装の中心は =init.el= の =doom!= ブロックで対象モジュールと
フラグを有効化すること。=config.el= ではなくモジュール選択の変更なので =doom sync= が
必須になる。

doom-first の調査結果と確定方針:

- LSP クライアントは lsp-mode（=:tools lsp= をフラグ無しで採用。=+eglot= は使わない）。
  =+peek= は付けない（=lookup= の =gd= 等を標準のジャンプ挙動のまま保つ。必要なら後で
  =(lsp +peek)= に変更可能）。
- =+tree-sitter= 系フラグの前提として =:tools tree-sitter= を有効化する。現環境は
  Emacs 30.2 + TREE_SITTER ビルドで利用可。tree-sitter 文法は初回利用時に doom/treesit が
  導入を促す。
- Ruby/Node のバージョン管理は mise。doom の =+rbenv= / =+rvm= / =+chruby= は付けず、
  PATH 経由で解決する。GUI Emacs（macOS Finder/Dock 起動）が shell の =$PATH= を継承せず
  mise shims 配下のバイナリ（ruby-lsp, typescript-language-server 等）を見つけられない
  問題には、doom 公式の =doom env=（=$PATH= を含む環境変数をスクレイプして envvar ファイル化、
  起動時に読み込む）で対処する。これは doom が =exec-path-from-shell= より推奨する方式で、
  =config.el= へのコード追加は不要。

言語サーバー本体（ruby-lsp / typescript-language-server / sourcekit-lsp /
vscode-langservers-extracted）のインストールは環境構築であり、設定リポジトリの対象外。
lsp-mode は未導入時に自動インストールを促す。

* やること

実装対象は [[file:../../init.el][init.el]] の =doom!= ブロック。各行は「コメントアウトされた既存行を
有効化（フラグ付与）した最終状態」に収束させる。既に最終状態なら変更しない（冪等）。
=add-to-list= 的な追記ではなく既存行の置換なので、=/sync-implementation= 実行時は対象行を
一意に特定して置換する。最後に =doom sync=（ホスト側はユーザー依頼。docker batch は自動実行）。

** DONE [#A] req-5.1 =:tools lsp= と =:tools tree-sitter= を有効化する

=:tools= ブロックで以下の2行を最終状態にする。

- =;;(lsp +eglot)      ; M-x vscode= → =lsp              ; M-x vscode=
  （lsp-mode 採用。=+eglot= も =+peek= も付けない）
- =;;tree-sitter       ; syntax and parsing, sitting in a tree...=
  → =tree-sitter       ; syntax and parsing, sitting in a tree...=

** DONE [#A] req-5.2 =:lang ruby= を =+rails +lsp +tree-sitter= で有効化する

=:lang= ブロックの ruby 行を最終状態にする。

- =;;(ruby +rails)     ; 1.step ...= → =(ruby +rails +lsp +tree-sitter) ; 1.step ...=
- バージョン管理フラグ（=+rbenv= / =+rvm= / =+chruby=）は付けない（mise 前提）。

** DONE [#A] req-5.3 =:lang javascript= を =+lsp +tree-sitter= で有効化する

TypeScript/React は javascript モジュールが担当（TS は js モジュール、JSX/TSX は
=+tree-sitter= 必須）。

- =;;javascript        ; all(hope...= → =(javascript +lsp +tree-sitter) ; all(hope...=

** DONE [#A] req-5.4 =:lang swift= を =+lsp +tree-sitter= で有効化する

- =;;swift             ; who asked for emoji variables?=
  → =(swift +lsp +tree-sitter) ; who asked for emoji variables?=
- サーバーは sourcekit-lsp（Xcode/Swift toolchain 同梱）。

** DONE [#B] req-5.5 =:lang web= を =+lsp +tree-sitter= で有効化する

- =;;web               ; the tubes= → =(web +lsp +tree-sitter) ; the tubes=
- HTML/CSS/SCSS 等（React の CSS、Rails の erb/haml/scss）。

** DONE [#B] req-5.1 mise 管理下バイナリを GUI Emacs に見せる（doom env）

- config.el へのコード追加はしない。doom 公式の envvar ファイル方式を採る。
- ホスト（macOS）の shell に mise が有効（shims が =$PATH= 上にある）状態で
  =doom env= を実行し、=$PATH= 等をスクレイプした envvar ファイルを生成する。GUI Emacs は
  起動時にこれを読み込み、ruby-lsp / typescript-language-server 等を解決できるようになる。
- これはホスト・macOS 固有の手順のため、=/sync-implementation= では自動実行せずユーザーに依頼する
  （docker/Linux では検証対象外）。
